A private repo for the source, a public one for the site

October 14, 2026

This site is a Next.js app, but the code you're reading it through isn't public. The source lives in a private repository, and only the built HTML, CSS and JavaScript go to the public tuhinatha.github.io repository that GitHub Pages serves. Here's how that's wired up.

Why split it

GitHub Pages serves a user site from a repository named <username>.github.io, and on a free account that repository has to be public. I wanted to keep drafts, notes and work-in-progress out of view, so the site uses two repositories:

RepositoryVisibilityContains
portfolioPrivateThe Next.js source
tuhinatha.github.ioPublicOnly the generated out/ folder

Exporting a static site

Pages only serves files, so there's no Node server to render pages on request. Next.js handles this with a static export:

const nextConfig: NextConfig = {
  output: "export",
  trailingSlash: true,
  images: { unoptimized: true },
};
  • output: "export" writes every page to out/ as plain HTML at build time.
  • trailingSlash: true turns /projects into out/projects/index.html, which Pages serves directly instead of redirecting.
  • images: { unoptimized: true } turns off the image optimizer, which needs a server.

Blog posts like this one are MDX files. The file name becomes the URL, and every post is rendered to HTML during the build, like the other pages.

Publishing on every push

A GitHub Actions workflow in the private repository runs on every push to main. It builds the site, checks out the public repository next to it, and copies the output across:

- run: pnpm install --frozen-lockfile
- run: pnpm build

- name: Check out the public site repository
  uses: actions/checkout@v4
  with:
    repository: TuhinAtha/tuhinatha.github.io
    ssh-key: ${{ secrets.PAGES_DEPLOY_KEY }}
    path: site

- name: Publish the build
  working-directory: site
  run: |
    rsync -a --delete --exclude .git --exclude README.md ../out/ ./
    git add -A
    git commit -m "Deploy ${GITHUB_SHA::7}"
    git push

rsync --delete makes the public repository an exact mirror of out/, so deleted pages disappear too. Each deploy commit names the source commit it came from, which makes it easy to trace what's live.

Authenticating with a deploy key

The workflow's built-in GITHUB_TOKEN can only write to the repository it runs in, so it can't push to the public one. Instead the workflow uses an SSH deploy key:

  1. Generate a key pair just for this.
  2. Add the public half to tuhinatha.github.io as a deploy key with write access.
  3. Store the private half in portfolio as the PAGES_DEPLOY_KEY Actions secret.

A deploy key is scoped to a single repository, so even if it leaked, it couldn't touch anything else on the account.

One gotcha: Jekyll

By default, GitHub Pages runs every site through Jekyll, which ignores folders starting with an underscore. Next.js puts all its JavaScript and CSS in _next/, so without a fix the HTML loads with no styles or scripts. An empty public/.nojekyll file, which ends up at the root of out/, tells Pages to skip Jekyll and serve the files as they are.

The result

Writing a post now means adding an .mdx file, committing and pushing. A minute or two later it's live, and the source stays private.
